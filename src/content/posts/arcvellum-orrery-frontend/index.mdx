ArcVellum 的前端核心不是一组与星空并列的仪表盘。叙事星仪本身承担项目导航、状态观察、创作交互与作品阅读入口，其他面板围绕它按需出现。

这种设计服务于长篇作品的特殊认知需求：作者既要知道当前任务，也要保持对章节顺序、人物关系、未兑现承诺和整体节奏的感觉。普通列表擅长精确检索，空间视图擅长形成整体记忆。星仪把两者结合。

## 2.5D 场景模型

场景使用透视、深度分层、视差、尺度和雾化制造空间感，节点本身保持清晰的二维排版与命中区域。它避免把所有信息做成复杂 3D 物体，也避免平面地图难以容纳不同题材。

主要层次包括：

1. 全景天幕，承载星云、噪点、微光和远层纹理；
2. 章节主脉，表达时间、节奏与作品推进；
3. 场景簇，围绕章节锚点组织更细粒度节点；
4. 人物与关系层，显示参与、影响、承诺和冲突；
5. 仪器层，显示任务、健康、交付与当前选择；
6. 窗口层，承载正文、档案、规则、决策和 Agent 会话。

视觉元素应属于对应层。天幕噪点随相机形成稳定远景，节点光效随作品状态变化，窗口保持清晰而不与场景深度一起缩放。

## 相机交互

用户可以在场景中全向平移、滚轮缩放和旋转视角。左键用于选择与拖拽场景，中键可承担视角或平移操作，具体映射需要保持可发现且兼容触控板。

相机遵守几项原则：

- 选择章节时对准章节簇重心，不只定位某一个场景；
- Z 轴移动保持方向一致，不在越过临界角后反转；
- 聚焦动画使用可中断的缓动，用户操作立即接管；
- 视角旋转可以自由，但提供一键回正和适合阅读的默认视角；
- 拖动、聚焦、切换布局后，窗口尺寸和形状保持稳定；
- 当前章节、任务和正文入口不会因距离完全消失。

## 布局语法

同一 Projection 可以使用不同构型。每种构型需要表达文学关系，而非只换几何形状。

### Spine

章节沿有起伏的时间主轴排列。横向距离由故事时间与篇幅共同决定，纵向曲率受张力和节奏影响。适合查看全书顺序。

### Weave

多条人物或支线轨迹围绕章节锚点交织。曲线使用连续切线与受控振幅，避免密集绕圈。

### Constellation

章节作为星簇核心，场景在局部轨道和重力方向上分布。适合观察同章内部关系和跨章人物轨迹。

### Loop

适合回环结构。曲线保持足够半径与开放间隙，时间方向明确，避免形成紧凑线团。

### Stage

章节沿舞台深度和幕次排列，场景像调度位置。主轴保持层次，不能把所有节点压在中心。

### Chambers

适合地点或阵营分区明显的作品。章节顺序仍由主脉连接，局部场景进入语义舱室。

布局算法应确定性复现。相同项目 revision、构型和种子得到相近坐标，用户才能形成空间记忆。

## 曲线与章节锚点

章节主曲线采用平滑样条或受控 Bézier 段，切线连续，曲率带有呼吸。章节锚点落在曲线上，场景通过局部曲线连接锚点。

远景关系可以连接每章场景节点的重心，近景展开为场景到分支、审查、问题和承诺的具体曲线。人物聚焦保留全景高亮轨迹；章节聚焦让全书主脉适度变暗，同时高亮该章内部所有关系。

曲线密度由视口、语义优先级和边束策略控制。减密不意味着删除高价值关系，而是把远景细边聚合成可恢复的主线。

## 节点视觉

节点可以采用文字主导的排版化天体：编号、标题、状态、短摘要与关键指标构成清晰层级，几何边框和光晕只提供状态线索。

视觉规则包括：

- 正式完成节点更亮、更稳定；待处理节点较暗，但保持可读；
- 当前任务使用独特脉冲和方向信号；
- 章节节点不叠加多层无关星环；
- 场景、人物、分支、审查和承诺具有可辨识的字体与符号；
- 节点尺寸随语义层级变化，避免全书视图把文字压到无法识别；
- 标签去重和碰撞抑制优先于粗暴隐藏。

点开节点后，详情窗在节点附近出现，带空间来源动画。多个窗口可以同时打开、拖动和调整大小，且不会互相覆盖关键控制。

## 星仪中的创作星链

工作流可以呈现为具有文学意义的创作星链。规划、人物、事件、推演、正文、审查与交付成为可交互阶段节点；任务 sidecar、completion marker 和命令细节留在内部。

用户看见的是：

- 当前可以点亮的创作动作；
- 需要补足的人物、节奏或情节条件；
- 已经形成的正文、审查和状态变化；
- 尚未解锁的后续阶段及其原因。

前端不改写 CLI Gate，只把 Gate 编译成具有叙事意义的空间状态。这样保留后端可靠性，也降低普通用户面对工程术语的负担。

## 环绕式仪表

推进、决策和规则位于上方，健康状态保持左侧窄栏，设置位于右上角，交付按钮随 readiness 点亮，正文长卷靠上方左侧打开。仪表在星仪模式中直接工作，不跳转成另一套控制台。

窗口使用深色或半透明低反射材质，与天幕协调。信息密度高的面板采用内部滚动、分段标题、可折叠详情和稳定尺寸。正文阅读窗可扩展到更大阅读宽度，避免长篇被挤在狭小卡片中。

## 任务可观测性

Agent 进程可以成为一组动态会话灯或提示卡。每个会话展示角色、模型、当前任务、最近事件、Token、持续时间、等待或阻断原因。点击后打开完整事件流和上下文摘要。

生成时，星链上的对应节点出现脉冲；分支产生时线路分叉；选择后候选淡出；Canon 写回时相关人物和世界节点点亮。动效来自真实事件，避免只做循环装饰。

## 性能与可访问性

星仪需要在 100、300 和 1000 场景级别分别验收。主要手段包括：

- 节点和边的视口裁剪；
- 标签分层与批量绘制；
- 几何缓存和增量更新；
- 边束与章节级聚合；
- 动效预算和减少动态偏好；
- DOM 窗口与 Canvas 场景职责分离；
- 键盘目录、搜索和列表作为等价导航。

背景与关系线不能抢夺文字对比度。色彩、字号、焦点轮廓和图例需要在桌面分辨率、缩放比例与不同显示器上验证。

## 视觉验收方法

实现完成后，使用真实项目进行截图和交互验收，至少覆盖：

- 全书章节视图；
- 全书场景簇视图；
- 聚焦章节和人物；
- 多窗口、顾问窗和正文长卷；
- 完成与未完成状态；
- 关系高亮和远景聚合；
- 旋转、缩放、全向平移与返回默认视角；
- 桌面安装版与开发 Web 版的一致动画。

星仪的评价标准包括美观、沉浸和记忆点，也包括能否准确回答：作品走到哪里，当前为什么停在这里，读者接下来可以做什么。
