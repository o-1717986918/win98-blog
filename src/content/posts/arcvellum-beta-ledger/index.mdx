## 先把已经站得住的部分写清楚

v0.99.0 的真实长篇闭环交付 2 章、6 场景和 30,080 个中文内容字符，scene、longform、review、export 四条路线合计有 295 项正式检查，发布证据记录为零 blocker、零 warning、零 todo。

Python 套件在 v0.99.0 有 1,274 项通过（一项跳过），v0.99.1 增长到 1,282 项（一项符号链接环境跳过）；Vue 从 60 个文件、186 项断言增长到 65 个文件、200 项断言；Pi Worker 保持 75 项测试。Playwright 增加了 100、300、1000 场景的规模验收。

这些数字能支持的结论是：已有主路线有可重放的证据，模块化没有靠删测试换取绿灯，长篇正式路线不再只在小型 fixture 上成立。

## 再把不能从这些数字推出的结论划掉

一次真实闭环不证明所有题材、所有项目尺度或所有模型供应商都具有同样稳定性。测试数量也不证明安装、升级、离线启动和卸载已经在独立干净虚拟机中完整走过。

当前 Windows 证据覆盖了真实编译、静默安装、修复安装、sidecar 启停和 updater 签名，但未独立完成干净 VM 上的旧版升级、断网启动和卸载残留检查。视觉烟测被 Escape 中断，所以不能把“窗口能启动”写成“用户已点完核心流程”。

## 千场景证明了“没丢节点”，也暴露了一笔真债

v0.99.1 对 100、300、1000 场景的星仪做了视觉验收，重点检查所有节点保留、碰撞降级只隐藏标签而不删除节点、交互仍可选中与聚焦。API projection 在千场景约 0.37 秒，但浏览器首次视觉完成约 46.3 秒，Orrery 主 chunk 约 513.65 kB（gzip 161.90 kB）。

这个对比将性能瓶颈定位在浏览器首渲染与 Orrery 加载，而非规划内核。它是一条很具体的 Beta 债务：节点语义已被保住，但千场景首次进入还不能被称为可接受的交互性能。

## v0.99.1 去掉了什么上限，又刻意没有去掉什么

经过显式授权，`full_auto` 移除了项目自定的任务数、运行时长、成本和到期上限。这不等于“永不停止”：用户暂停、供应商配额、正式门禁、无进展检测和失败恢复仍然存在。

这个变更很好地说明产品边界：成本上限是用户授权问题，门禁是项目正确性问题。前者可以被明确授权放宽，后者不能因为用户想让 Agent 多跑一会儿就被跳过。

## 下一次发布应该用哪些问题验收

| 领域 | 已有证据 | 下一次门禁 |
|---|---|---|
| 长篇路线 | 2 章 / 6 场景 / 30,080 字 | 更长跨章项目与不同题材复查 |
| Agent Runtime | 双工作区、租约、恢复、预检 | 更多供应商与故意中断注入 |
| 星仪 | 100/300/1000 节点不丢失 | 千场景首渲染、懒加载与 chunk 拆分 |
| Windows | 真实包、安装/修复、签名 | 干净 VM 升级、离线、卸载与真实 UI 点击 |
| 架构 | 零新债、零环、模块图 | 逐步收缩 16 / 110 历史债务与核心合同缺口 |

只要这张表仍和每次发布一起更新，Beta 就是一份可行动的诚实账本；如果只剩一枚长期贴在 logo 旁的徽章，它就什么都没有说。

## 性能证据必须按链路拆开

“千场景需要 46 秒”如果只留下一个总数，很容易把优化方向带错。后端 projection 约 0.37 秒，说明层级、关系与动作描述的构建不是首要瓶颈；主 chunk 体积、Pixi 初始化、千节点布局、DOM 标签、碰撞处理和首帧相机取景共同组成浏览器成本。下一轮应分别记录下载、解析、投影消费、布局、Canvas 可用和可交互时点。

语义缩放也不是简单隐藏节点。书级首屏必须保留章节核与场景星点，进入章节后才提高标题密度；碰撞只能抑制副文案，不能删除事实。真正可接受的优化可能包括按焦点延迟生成标签、把天穹与工作面拆 chunk、缓存稳定布局、在 Worker 计算碰撞，但不能用只渲染前几十个节点伪造性能提升。

## 发布矩阵要区分“代码绿”和“产品可交付”

单元测试、类型检查和构建绿色属于代码证据；打包、签名、安装、升级、离线与卸载属于分发证据；用户能从创建项目走到场景晋升、阅读与导出属于产品证据。三组任一缺失，都不能由另一组的测试数量代替。

ArcVellum 已经把这些证据放进不同文档与流水线，但 Beta 账本还需要维护证据日期、运行环境、对应 revision 和未完成原因。尤其 Windows 的真实虚拟机验收不能由开发机静默安装替代，千场景的可交互时间也不能由 API benchmark 替代。

## 下一版应减少多少债，而不是增加多少功能

v1.0 前最有价值的增量未必是新 workbench。优先级更高的是：把任务命令从字符串收紧为 argv，把人类可读 JSON 变成版本化 schema，拆清 `expected_outputs` 的确定性产物、Agent 产物和完成证据，完成干净 VM 分发矩阵，并让星仪首屏成本进入可持续预算。

这些目标都可判定、可回归、可在失败时留下证据。Beta 的意义正是在这里：不是用“仍在测试”回避承诺，而是把通往稳定版的剩余问题改写成可以被下一次构建证伪或证明的门禁。
