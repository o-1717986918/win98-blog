“五卷、五十万字”看起来是一项清楚的需求，实际只给出了容器规模。若大纲只有一部中篇的事件量，模型常见的应对方式会让每个场景变长、心理解释增多、同一情绪反复出现，最后仍然提前结束。ArcVellum 的长篇规划模块先判断故事是否拥有足够的可叙述变化，再把篇幅目标传递到每一个正式场景。

## 规划输入

长篇规划读取以下信息：

- 总目标字数、卷数、预期章节数与交付形式；
- 小说类型及其常见叙事密度；
- 故事覆盖的时间跨度；
- 主线问题、人物弧、世界变化和终局状态；
- 已知关键事件、关系转折、揭示、承诺和兑现；
- 文风对叙述密度、对话比例与场景长度的影响；
- 用户要求的详略、阅读节奏和篇幅容差。

这些输入会形成一个版本化 Word Budget 与 Scene Inventory。Agent 负责理解题材和设计事件，确定性模块负责统计、校验、分配和欠账检测。

## 从字数目标反推叙事容量

总字数被拆成多级预算：

```text
Work target
  -> Volume budgets
  -> Chapter budgets
  -> Scene targets
  -> Scene function and expansion inventory
```

简单平均只能提供初始尺度。真正的分配还会考虑：

- 高潮、重大揭示和关系断裂需要更多现场化篇幅；
- 过场、时间跳跃和信息搬运应保持压缩；
- 调查、战争、成长、悬疑、家族史等类型拥有不同的事件密度；
- 时间跨度越长，越需要明确哪些阶段采用概述，哪些阶段进入场景；
- 多视角作品需要为视角切换和线索汇合预留结构空间；
- 文风偏简洁时，同一事件库存支撑的字数更少，需要增加真实事件量。

规划模块会生成“剧情库存说明”：每卷需要完成哪些不可替代的状态变化，每章承担哪些义务，每个场景实现什么功能。字数来自这些义务的充分展开。

## 场景库存承担什么

一个合格场景至少要改变一项可观察状态：

- 主线获得推进或新阻力；
- 人物作出带代价的选择；
- 关系强度、信任或权力发生变化；
- 信息被揭示、误读或重新解释；
- 读者问题被提出、延迟、部分回答或反转；
- 承诺获得兑现，或延期产生新的代价；
- 世界状态、时间线或资源发生变化；
- 下一场得到明确压力和入口。

只有“补充设定”“人物闲聊”“重复强调情绪”的场景会被标记为功能不足。系统可以建议合并、删除或增加真正的行动与后果。

## 字数合同怎样进入正文链路

预算一旦生成，目标会写入场景定义，并被以下环节共同读取：

1. Context Packet 提醒当前场景和章节的剩余义务；
2. Composition 形成 `word_count_target`、容差和展开策略；
3. 正文任务将目标字数列为硬合同；
4. Review 只统计正文内容，排除标题、流程说明、Canon 备注和 Markdown 控制信息；
5. Promotion 重新计算精确候选的内容字符；
6. Chapter Workspace 汇总实际字数、欠账和超额；
7. Longform Audit 判断全书趋势是否仍能抵达目标。

这条链路修复了“预算文件已经存在，写作 Agent 却从未读取”的典型断点。目标字数成为场景的正式属性，无法只停留在规划报告里。

## 中文字数与机器字符

中文创作常把汉字与标点都视为阅读篇幅的一部分，程序则可能统计 Unicode 字符、非空白字符、词元或字节。ArcVellum 将用户目标定义为“中文内容字符”，正文统计包含汉字和有效中文标点，排除 Markdown 标记、工作流程与非正文元数据。

模型上下文预算仍按 Token 管理，两者通过经验映射连接。映射只用于预估请求规模，正式篇幅验收始终回到正文内容字符。这样可以避免 Token 数、英文词数和中文阅读字数混用。

## 节奏曲线参与分配

篇幅计划同时建立宏观张力曲线。章节会被标注为铺垫、积累、转折、高潮、余波或迁移阶段。场景继续细化：

```yaml
rhythm_role: confrontation
pace: fast_to_slow
density: high
narrative_distance: near_then_mid
scene_turn: 主角从试探转为承担代价
reader_effect: 短暂安心转化为新的怀疑
```

系统据此控制动作、对话、叙述、心理与环境的比例。高潮可以充分现场化，过场保持短而清楚，余波留出呼吸。章节之间的节奏差异会进入星仪热力层和质量面板，作者可以在宏观上调整。

## 场景桥接让库存形成因果链

每个场景都拥有进入压力和离开钩子。常见钩子包括未解决问题、情绪债、关系压力、物件、误会、承诺、危险和被延迟的伏笔。下一场要明确接住其中至少一项。

```yaml
incoming_from_previous:
  - 接住上一场的隐瞒压力
outgoing_hooks:
  - type: plot_pressure
    content: 对手依据错误线索开始行动
  - type: reader_question
    content: 信件为什么提前出现在房间里
```

桥接合同让场景库存拥有方向。单场质量再高，若没有接入前后因果，仍会在 Review 中暴露为“场景孤岛”。

## 滚动规划与未来阴影

长篇创作无法在开篇穷尽所有细节。ArcVellum 采用滚动规划：全书保留高层目标，当前卷和近期章节拥有更高分辨率，远期保持可调整的 Future Intent。每完成一个场景，系统更新已知事实、状态变化和读者义务，再检查近期规划是否仍然可行。

新角色、意外分支、篇幅欠账或连续两次修订失败会触发重规划建议。重规划形成带版本和原因的计划补丁，不能静默覆盖原目标。

## 欠账检测与扩场景任务

系统比较目标与实际正文，生成三类信号：

- **局部欠账**：单场未达到合理容差，且场景义务尚未充分实现；
- **结构欠账**：章节目标明显不足，需要新增行动、后果或关系变化；
- **库存欠账**：全书事件量无法支撑总篇幅，需要扩展子线、时间段或人物弧。

局部欠账可以进入 `candidate-revision`。结构欠账会生成扩场景建议。库存欠账要求回到长篇规划，避免用形容词、心理重复和无效对话填充篇幅。

## 规划 Gate

正式场景生成前，系统检查：

- Word Budget 已存在并完成 Agent 规划任务；
- 当前场景拥有机器可读的目标字数；
- 章节目标与全书预算来源一致；
- 场景功能、节奏与桥接合同完整；
- 剧情库存能够解释预期篇幅；
- 预算更新没有使已经晋升的正文失去归属。

任何缺失都会阻止正文任务签发。规划因此成为创作链路的输入合同，而非可选参考。

## 作者能够调整什么

前端的规则与策略面板允许作者管理总体字数、容差、节奏模式、章节详略、文风和部分 Lint 阈值。用户修改形成显式配置版本，并使受影响的未来任务失效重编译。已经晋升的正文不会被自动改写。

规划目标最终服务于阅读。字数是容量约束，剧情库存提供内容，节奏曲线安排注意力，场景桥接维持因果。四者共同工作，才能让一部长篇在增长过程中保持结构和呼吸。
