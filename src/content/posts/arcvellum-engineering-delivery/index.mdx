文学工程内核需要大量精确证据，普通作者的工作界面却不能充满 YAML、JSON、路径和终端命令。ArcVellum Studio 位于两者之间：向下调用稳定应用服务，向上呈现作品语言。

## 产品工作面的组成

| 工作面 | 用户要解决的问题 |
|---|---|
| 项目入口 | 新建、打开、切换和定位作品 |
| 叙事星仪 | 理解全书结构、任务、关系与进度 |
| 正文长卷 | 阅读已晋升正文，边创作边阅读 |
| 档案 IDE | 浏览与编辑人物、世界、场景和风格资产 |
| 创作顾问 | 用自然语言提问、下达方向和请求项目动作 |
| 决策中心 | 处理分支、Canon、修订和扩纲选择 |
| Agent 运行中心 | 观察会话、任务、事件、成本和阻断 |
| 连接与模型 | 配置 Provider、模型与角色路由 |
| 交付中心 | 检查 readiness，导出 Markdown 与 DOCX |

这些界面共享同一应用状态和 Narrative Projection，避免每个页面独立推断项目进度。

## 项目目录与桌面安装

安装后默认作品库位于用户文档目录下的 `ArcVellum/Works`，兼顾可发现性、备份和升级安全。应用程序文件留在安装位置，用户作品与安装包分离，覆盖升级不会碰触正文。

用户可以通过桌面目录选择器切换作品库，也可以输入路径。Web 开发模式受浏览器安全限制，只支持可授权的目录操作；Tauri 桌面桥提供真正的本地目录选择。

项目切换会更新当前投影、SSE 订阅、阅读器目录和自动创作上下文。旧项目的运行会话按租约收敛，不应继续把事件推入新项目界面。

## 模型连接

连接页在用户打开时才加载 Provider 数据，减少启动阶段的网络与进程开销。常用 Provider 提供预设，自定义 OpenAI-compatible 端点允许用户连接其他服务或本地网关。

模型选择按角色持久保存：主创、审查、规划、顾问和轻量结构化任务可以选择不同模型。切换后，新任务使用新配置；正在运行的任务保留原会话，确保结果可追踪。

API Key 进入本地凭证机制，不写入作品项目、普通配置、任务包或诊断报告。连接测试需要区分 DNS、认证、模型名、流式协议和余额错误，避免把所有失败都显示成“无法连接”。

## 创作顾问

顾问是只读项目控制台与自然语言入口。它读取经过包装的项目快照，可以回答：当前卡在哪里、某个人物发生了什么、下一项可执行任务是什么、某个决策会影响哪些章节。

顾问没有直接文件权限。它可以生成白名单动作提案，例如开始下一步、打开节点、选择已存在选项、调整允许的创作参数。用户确认或自动化策略批准后，动作进入正式应用用例。

顾问使用可选择人格和自定义系统提示，输出支持 Markdown 流式渲染。悬浮窗保持手机聊天比例、内部滚动和稳定拖动尺寸。关键阻断、人工决策或长任务结束时，顾问可以依据真实事件主动提示，避免周期性打扰。

## 档案 IDE

档案界面采用深色 IDE 模式，左侧是类型与文件树，中间是结构化编辑或 Markdown 编辑，右侧展示来源、版本、引用和影响范围。

用户可以修改正式资产、创建候选、比较差异和手动晋升。用户编辑拥有明确优先级和审查策略；对正式 Canon 的直接修改需要生成 revision 与影响提示，使后续上下文重新失效和编译。

前端展示经过字段化包装的数据，用户仍能按需查看原始文件。资产管理不能只提供漂亮卡片，也要支持搜索、筛选、去重、引用定位和批量检查。

## 正文阅读器

阅读器只拼接已晋升正文，按卷、章、场景形成连续目录。候选、Review notes、世界状态变化、Canon patch 和工作流痕迹不会进入阅读正文。

良好阅读体验包括：

- 可调字体、行高、段宽、主题与章节间距；
- 章节目录、场景定位和阅读进度；
- 新场景晋升后增量出现；
- 保留当前位置，不因 SSE 更新跳回顶部；
- Markdown 语义渲染，不暴露源码符号；
- 一键定位正文对应的星仪节点与审查状态。

正文长卷在星仪中可用紧凑窄窗打开，也可以扩展为完整阅读工作面。窗口尺寸要能容纳真实长篇，不以 demo 文本为上限。

## 自动创作模式

Studio 提供协作、监督自动和全自动模式。全自动模式需要用户给出创作方向、约束和授权边界，随后 Autopilot 循环领取任务、运行 Worker、预检、提交并推进。

无人值守运行具备：

- 无进展检测和有限修复；
- Provider 重试与模型故障分类；
- 决策策略和高风险例外；
- 进程租约、取消和重启恢复；
- 预算观测，不以隐藏硬上限阻断正常作品；
- 到达正文晋升、章节完成和交付节点的可见里程碑。

自动化不能把阻断文案当作失败终点。对可修复合同错误，系统应给出重新签发、补证据或回退步骤；对需要用户决定的事项，决策卡必须出现且选择后被消费。

## 交付管线

交付中心从正式正文清单构建作品，不扫描所有 Markdown。管线按照以下顺序工作：

```text
promoted prose manifest
  -> chapter ordering
  -> workflow artifact filtering
  -> punctuation normalization
  -> front matter and styles
  -> Markdown / DOCX render
  -> visual and structural verification
  -> release manifest
```

DOCX 能力包括标题层级、段落样式、页眉页脚、目录准备、中文字体、分页和图片处理。输出后需要重新渲染或读取文档，检查草稿标记、场景编号、Canon 信息和不可见流程痕迹是否被过滤。

## 桌面壳与本地服务

Tauri 负责安装、应用窗口、目录选择、本地进程生命周期、自动更新和安全桥接。Vue 客户端通过本地认证 API 与 FastAPI 服务通信，SSE 提供项目与 Agent 事件。

桌面启动应隐藏辅助终端窗口，等待后端、Worker 和前端资源就绪后平滑进入正式界面。加载动画反映真实阶段：本地服务、作品库、模型目录和投影，而不是固定计时。

本地服务默认监听 `127.0.0.1`，桌面端使用启动令牌。诊断包过滤凭证、正文全文和完整用户路径。Windows 安装包包含固定运行时；macOS 预览包需要继续完成签名、公证与干净机器验证。

## 用户帮助与产品信息

帮助入口提供视觉引导、模块说明、常见阻断和操作恢复，不作为装饰按钮。首次使用通过逐步聚焦解释项目、星仪、正文、模型连接与自动创作。

设置中的关于页展示版本、更新状态、开发者信息、协议、隐私、诊断和未来官网入口。技术术语在高级详情中保留，主要界面使用作品和创作语言。

Studio 的成功标准是让严格内核保持可见的可信感，又不要求作者先成为 CLI 维护者。用户能理解当前状态、继续工作、阅读结果和取得干净交付，这套产品工作面才真正成立。
