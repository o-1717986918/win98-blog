如果 Vue 客户端直接读取 Canon 文件、任务账本、正文目录、人物状态和审查报告，再自行拼出“当前作品”，星仪很快会变成第二套业务内核。它在某次会话里看似正确，却无法回答刷新后如何恢复、投影版本变化怎样迁移、同一场景为什么在阅读器和星仪中状态不同。

ArcVellum 的解决方案是 Narrative Projection：后端把正式项目状态编译为稳定、版本化、只读的作品图，前端只负责空间解释。

## Projection v4 拥有什么

ADR-002 把星仪定义为项目级空间操作系统。书、章、场景、人物、世界、文风、分支、审查、决定与正式正文不是分别抓取的图，而是同一 creative constellation 的不同语义焦点。

投影拥有稳定身份、层级、生命周期、关系、可用动作和来源提示。焦点从 `book` 切到 `chapter` 时，并不是请求另一份真相，而是改变强调范围与相机意图。这个差别使返回全书、聚焦章节、打开节点详情和从正文反向定位可以共享同一 identity。

## 后端与前端的分权

| 后端拥有 | 前端拥有 |
|---|---|
| 层级、生命周期、动作是否可用、稳定身份 | 2.5D 坐标、语义缩放、动效、窗口几何 |
| 正式状态和来源证据 | 碰撞抑制、标签密度、镜头过渡 |
| typed action descriptor | 将动作交给已有 command / use case |

这个边界最重要的结果是：节点发亮不能让任务完成，拖动场景不能改变章节顺序，点击“晋升”也不能由前端拼一个 CLI 命令。动作由投影中的 descriptor 描述风险、确认策略和目标，再经 action dispatcher 交给已存在的应用命令或 human-choice endpoint。

## 六种空间语法不改变事实

Spine、Braid、Strata、Constellation、Loop 和 Stage 是同一组节点的六种排布语法。Spine 适合检查时间主轴；Constellation 用章节核和局部场景轨表达作品家族；Stage 强调幕与表演位置。切换语法只改变坐标，不改变 node id、关系和状态。

布局引擎保持确定性。同一 revision、同一构型和同一项目种子应该得到可复现坐标，否则每次打开项目都会重排，作者无法建立空间记忆。章节核、场景黄金角轨道、长项目纬带容量和有限坐标都有单元测试，而不是由随机粒子决定。

## 为什么默认只显示“作品主脉”

v0.99 的真实压力项目有 1148 个工程事实。把它们全部画出来符合数据完整，却会让章节顺序、场景与主要人物消失在维护资产里。主脉模式保留项目原点、全部章节、当前或阻断场景、主要人物、人工决策及一跳证据；普通 Canon、预算、候选镜像、已完成审查等仍在投影、档案和检索中，但不争夺默认视野。

这不是删数据。全书 / 主脉从 1148 个事实中显示 69 个常态节点，章节 / 主脉显示 78 个，切换“全部”仍可恢复 1148 个。选中、搜索、当前、阻断节点可以穿透筛选。真正的设计目标是同时公开“当前显示多少主脉节点”和“总共有多少工程事实”，避免用户误解为丢失。

## 关系线也要有语义层级

章节 Catmull-Rom 主脉由底光、实体轨道与流动信号构成；人物、证据与桥接关系退到次层。聚焦一章时，其他章节不消失，只降低强度。否则局部查看虽然干净，作者却会失去它在整本书中的位置。

同样，标签碰撞只能隐藏副文案，不能让星体本身不可点击。章节编号、场景星核、人物星核和关系事实仍要保留。列表替代视图也不是装饰性的“无障碍模式”，而是空间关系无法由键盘或屏幕阅读器完整表达时的正式等价入口。

## v3 / v4 为什么都保留 revision 和 patch

长项目的投影不适合每个事件都整图重载。Projection 维护 revision，增量 patch 绑定 base 和 target revision；如果基线不匹配就拒绝应用，而不是把不完整增量硬塞进当前图。SSE 只负责传输变化，不能成为新的内存状态真相。

这套机制也解释了为什么 Demo 可以使用模拟内容，但必须明确标识。博客内嵌星仪沿用了投影、焦点、语法、动作端口和信息密度的结构，却没有连接真实项目；它能解释架构，不能冒充正式产品证据。

## 仍未解决的现实债务

v0.99.1 审计记录：1000 场景的 Projection API 约 0.37 秒，浏览器完整首帧仍可能达到 30–45 秒；星仪主 chunk 也仍然较大。责任边界已经把问题定位到 Orrery projection/layout/rendering，但定位清楚不等于性能已经解决。

下一步应该在 Feature 内做懒加载、分层首帧、空间索引、离屏缓存和渐进标签，而不能通过删除正式节点、让 Engine 返回残缺事实或把大型项目重新变成表格来掩盖债务。
