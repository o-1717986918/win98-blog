## 为什么在发布前后仍然大量出现“split”

v0.99.1 附近的提交记录中，能看到 projection、narrative layout、API route、workspace composition root 等一系列拆分。这些并不是为了让目录看起来更专业。在一个同时包含 Python 内核、FastAPI、Vue Feature、Tauri 壳和 Worker 的仓库里，单个文件很容同时成为业务真相、HTTP adapter、组装点和界面投影。

只要这种混合存在，修复一个界面事件就可能改变任务语义；拆分一个 router 就可能改变 revision 或默认参数。模块化的目标是让这些责任有可检查的所有者，不是把一个大文件平均切成十个小文件。

## 先有模块目录，再允许人修代码

仓库生成模块图和模块目录，给出每个模块的公开合同、主模块、adapter 与定向测试。新变更的推荐顺序是：先找到所有者，读公开合同，读一个真实 adapter 和一组定向测试，然后才在模块内实现。

只有当公开合同确实不足时，变更才分成“合同—adapter—调用方”三个可回滚批次。这样做也为 Agent 编程提供了更好边界：它不需要为了修一个 Feature 而读完整个仓库。

## projection 拆分不能改变星仪的世界

叙事 projection 有 v2/v3/v4 等版本，前端、API 和测试对 revision、节点总数、稳定 ID 与默认参数有明确预期。重构可以把数据准备、布局、视觉属性和 API 适配分开，却不能让同一项目重新打开后所有节点换位，也不能让“主脉”模式悄然丢掉内容。

所以拆分与确定性测试必须同步进行。模块图是人理解所有权的证据，稳定投影测试则证明内部切割没有改变外部世界。

## 16 个大文件和 110 个大函数没有被“清零”

模块化审计仍记录 16 个历史大文件与 110 个大函数债务。有些是成熟内核中较难立即切开的政策逻辑，有些是已经有测试覆盖却缺少足够迁移收益的历史结构。审计没有通过调大阈值把它们消失。

棘轮只要求零新增违规、零循环依赖、零 Studio 对 Engine internal 的导入。这是一种可信的债务策略：不声称一夜还清，也不允许新功能继续借债。

## 当前核心审查还指出了更深的合同缺口

`current-core-review` 将嵌入式内核判定为已经足以充当 policy kernel，同时列出不应被模块数量掩盖的问题：人类可读输出仍有未版本化的 JSON，任务命令仍有字符串而非 argv，schema 还缺执行策略，`expected_outputs` 混合确定性产物、Agent 产物和完成证据，required reading 路径也不够显式。

这些是下一轮模块化的真实起点。把文件拆小很容，把合同语义拆清才是架构工作。

## 四层所有权比目录数量更重要

目前最稳定的阅读方式不是背下所有包名，而是先辨认四层：foundation 只提供错误、时间、路径与序列化等低层能力；Engine 模块拥有工作流、Canon、审查、Prompt 与投影等业务合同；Studio/API 把用例投射成 HTTP、SSE 与桌面会话；Vue Feature 消费只读 projection，并通过 action port 请求既有用例。

依赖只能沿明确方向前进。前端不能根据某个节点颜色推断“可以晋升”，API 不能在路由函数里重写工作流，Runtime 也不能绕过 Prompt Registry 自行拼接正式提示。模块图的价值在于让这些越界能被静态检查和评审看见，而不是让架构图拥有更多盒子。

## Context、Prompt、Workflow 与 Review 是四个不同模块

Context Broker 负责从项目状态筛选与排序证据，输出带来源和预算的上下文包；Prompt Registry 负责版本化模板、变量契约和解析结果；Workflow State Machine 负责阶段、许可与恢复；Review CI 负责把审查发现转成可阻断的结构化结果。它们在一次 Agent 任务中连续出现，却不能被合并成“调用模型”。

例如上下文缺失应由 Broker 报告证据缺口，模板变量缺失属于 Registry 编译错误，任务租约失效属于 Workflow 状态问题，正文与 Canon 冲突才是 Review 结论。若四种失败最终都变成一段自由文本，自动恢复、统计和用户决策都会失去依据。

## 安全拆分需要一条可回滚迁移协议

实际拆分先固定公开合同与黄金测试，再提取纯函数或 adapter，最后移动 composition root 的组装。每一批都保持调用方可运行，避免“大重构分支”同时改变路径、默认值与业务语义。针对 projection，还要固定节点 ID、revision、默认参数、六种 grammar 的有限坐标与相同输入的确定性输出。

这也解释了为什么审计允许历史债务存在，却禁止新增债务：一个 500 行、被大量测试覆盖的稳定政策模块，未必比五个边界错误的新文件更危险。棘轮先阻止情况恶化，再按变更频率与合同收益偿还；重构完成的判据是所有权更清晰、回归证据不变，不是行数曲线好看。
