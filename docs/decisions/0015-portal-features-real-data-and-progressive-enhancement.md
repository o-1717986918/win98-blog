# ADR-0015：门户功能以真实数据和渐进增强接入

- 状态：Accepted
- 日期：2026-08-30

## 背景

ADR-0014 已确定首页在结构上参考 Mizuki，但仅有布局贴近不足以支撑“综合个人门户”。需要把内容发现、访客偏好和专用页面变成可使用的能力，同时避免为空缺内容建立样板页，也不能破坏 Astro 静态优先和文章三档外壳的隔离契约。

## 决策

1. 使用 `src/config/portal.ts` 作为门户功能注册表；功能必须有真实数据、明确入口和验证后才设为启用。
2. 首批启用项目、能力、时间线三个专用页面。条目只连接现有代码、文章、主题或公开笔记，不使用虚构项目、百分比能力条或占位里程碑。
3. 首页文章流在无脚本时完整可读；脚本只增强为每次展开六篇。发表日历按钮按真实发布日期筛选同一文章流，并提供显式清除操作。
4. 访客可用原生 `dialog` 控制辅助模块与信息密度；偏好仅写入当前浏览器的 `localStorage`，不产生网络请求。
5. 相册、日记、友链、追番、设备、AI 工具、音乐、Live2D 与壁纸保留为关闭状态，直到拥有真实内容、静态回退、性能边界和隐私说明。
6. 不引入客户端框架或整站状态管理；项目、能力和时间线的基础内容都由构建期 HTML 提供。
7. 门户扩展及桌面导航侧栏后的原始样式预算调整为单页 80 KiB、全站路由隔离样式 200 KiB；JavaScript gzip 预算不放宽。预算仍由构建失败强制执行。

## 后果

- 站点从“门户式版面”进入“可配置、可筛选、可继续扩展的个人门户”，并保持无脚本可访问。
- 新功能的完成条件从“存在页面”升级为“存在真实内容、配置开关、入口、降级与测试”。
- 后续增加相册或日记时，应先设计内容集合，再开启注册项；不能把演示数据写入正式页面。
- 小幅增加的 CSS 用于原生设置面板和三类真实功能页；对应上限被显式记录，后续增长仍会使构建失败。
