# ADR-0014：采用 Mizuki 式门户结构，同时守住本站视觉连续性

- 状态：Accepted
- 日期：2026-08-30

## 背景

首页已有成熟的重点文章、作者档案、主题、文章和学习笔记视觉，但各模块以大型展示区顺序排列，身份、近况与内容发现之间距离过长，整体更接近项目展示页。站点下一阶段目标是综合个人门户，Mizuki 的侧栏、时间流、日历与功能目录提供了可参考的信息架构。

用户明确要求：布局和功能向 Mizuki 靠拢，不以此替换本站原有视觉风格。

## 决策

1. 首页先进入响应式门户骨架：桌面三栏、中屏两栏、窄屏单栏；压缩后的重点文章作为“精选回看”移至内容末尾，不再挤占首屏。
2. 左栏承载不改造外观的作者档案与长期主题；中央只承载主阅读任务——文章时间流；右栏以紧凑学习笔记为首个入口，并继续承载发表日历、标签索引与站内入口。
3. 月历、标签、文章数量和主题数量全部在构建期由 Content Collections 生成，不使用伪造统计。
4. 继续使用 mist/abyss、语义 accent、原有字体、切角、细线、登记号与光谱批注；不复制 Mizuki 的色板、圆角玻璃卡、图标和动效。
5. 日记、相册、友链、项目、技能、设备、音乐、Live2D 等能力采用“真实内容集合 + 可配置组件 + 默认关闭 + 按路由加载”的渐进路线，不建立空页面；首批功能启用规则见 ADR-0015。
6. 不引入 Tailwind、Svelte、Swup、SPA 路由或常驻全局状态；`full/minimal/none` 隔离契约不变。

## 后果

- 首页更像可持续增长的个人门户，同时保持已有品牌识别。
- 页面信息密度提高，需要用断点测试、键盘焦点和内容长度审计持续防止拥挤。
- 门户功能的“可采纳”不等于一次性启用；动态功能必须先证明内容价值、静态降级、隐私和性能预算。
