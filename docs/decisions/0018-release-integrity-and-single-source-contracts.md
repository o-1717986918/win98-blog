# ADR-0018：发布完整性与单一事实契约

- 状态：已接受
- 日期：2026-08-31
- 取代：ADR-0011 中“运行时长期兼容旧主题别名”的局部决定

## 背景

项目审查发现发布门禁、搜索范围、笔记同步、路由 frontmatter、日期时区、浏览器存储和文档事实之间存在多套契约。部分测试冻结了源码写法，却没有验证最终页面和传递依赖；GitHub Pages 发布也没有强制执行真实浏览器回归。

## 决定

1. 生产发布统一依赖 `pnpm verify:all`，覆盖单元测试、完整求解器冒烟、静态构建、Pagefind、内容/封面/链接/锚点/体积审计与 Playwright。
2. `frontmatter.mjs` 复用 Astro Zod 枚举和默认值；已发布文章的主题引用由 Schema 保证，路由集成只消费规范化结果。
3. 每次进程使用同一 publication timestamp；日期展示和年月归档统一使用 `Asia/Shanghai`。
4. 公开笔记同步使用 manifest 差量清理，公开 frontmatter 不保存本地源路径；公开关系图只允许指向可发布笔记。
5. 搜索覆盖 Pagefind 中全部公开正文边界，并只允许摘要中的 `<mark>` 标签进入结果 HTML。
6. 浏览器持久化通过安全适配器访问，存储被禁用时不得阻断导航、开场退出或门户控制。
7. 主题运行时只接受 `mist` 与 `abyss`。历史别名在一次性迁移层转换，不进入核心 Schema 或运行时解析器。
8. 架构测试验证传递依赖边界；最终 HTML/资源隔离由构建审计验证；用户连接行为由 Playwright 验证。

## 后果

新增内容、入口和部署目标必须同时满足上述可执行契约。历史文档不再以整文件哈希冻结；当前事实优先读取 Schema、源码、测试、产物和后续 ADR。GitHub Pages 不解释 `_headers`，因此该文件只代表兼容主机配置，线上响应头需要在实际承载层单独核验。
