# ADR-0020：轻量的程序镜像与内容分离发布

- 状态：备选方案，未实施；2026-09-19 精简并明确学习笔记范围，后改为备选
- 原决定日期：2026-09-01
- 补充：ADR-0018、ADR-0019

## 背景

本 ADR 保留“独立内容仓库 + 服务器 builder”的完整设计，供后续选型比较；目前不授权据此迁移生产发布链。日常发布已选择 ADR-0021 的“Actions 构建产物、服务器只验收并切换”路线；前后端内容管理仍非当前实施范围。

当前 Astro 站点把程序、内容和最终 dist 一起构建进 GHCR 整站镜像。只修改一篇文章或笔记，也要重建、推送、拉取镜像并替换容器。另一方面，路由、首页、笔记关系、Pagefind、RSS 和 sitemap 均在构建期生成，不能只向 Nginx 挂载 Markdown 或轻量重载。

内容目录同时包含可执行 MDX import、Astro 组件、脚本和 Wasm，因此不能无条件视为低权限内容。项目目前为单作者、几十篇内容，不需要为了分离内容而先建设完整发布平台。

## 备选设计

1. 程序、依赖和可信特殊页面构建为固定 digest 的 builder 镜像。程序变更才更新该镜像；当前 GHCR 整站镜像保留为救援制品。
2. 普通文章、公开学习笔记及其媒体进入一个独立 Git 内容仓库。主题首期留在程序仓库，保持现有新增主题与共置组件契约；以后确有收益再评估纯数据主题。笔记仓库只保存公开投影；私人/草稿 Vault 条目不得进入远端仓库、builder 输入或公开产物。
3. 站主通过一条宿主机命令发布固定内容 commit。临时 builder 装配内容，执行完整 Astro 静态构建、Pagefind 和现有产物检查。纯内容发布不重建程序镜像。
4. 验证成功后生成不可变静态 release，并以同文件系统原子指针切换 current。Nginx 只读挂载 release 根，无 Git、Node、Docker Socket 和写权限；失败不改变 current，回滚只切换到已验证旧版。
5. 普通内容只允许受控 Markdown、元数据和媒体；任意 MDX import、Astro、JS、Wasm 和新交互仍走程序发布。一个 collection + slug 只能有一个事实源，迁移时须对照现有 URL 与产物。
6. 首期只有一个内容仓库、builder 镜像、发布/回滚脚本、单发布锁、release.json 和文本日志。复用现有 Astro Schema 与检查；不预建常驻 publisher、队列、任务数据库、Webhook、CMS、通用适配器或自动清理器。
7. 公开学习笔记与普通文章一样可以只改内容发布，但保持独立 notes 集合，不自动加入文章 RSS。笔记同步必须增加只导出公开投影的模式，覆盖新增、修改、撤回、附件、Wiki 关系、Pagefind、sitemap 与私人内容防泄漏。

## 预期代价与升级条件

内容发布仍消耗一次完整静态构建，服务器需要足够的临时磁盘、CPU 和内存。Git 内容仓库和 builder digest 提供版本追溯，保留少量旧 release 供无构建回滚。复杂发布状态、自动清理、远程后台和数据库只有在真实并发、容量或编辑需求出现后再增加。运行中的 Web 仍保持简单、只读。

## 后续可选：模板页面包

普通内容分离 P0–P3 稳定后，可做 P4 页面包试点：固定格式的正文、JSON 数据和媒体由内容仓库发布，程序侧一个小型静态允许列表选择已存在的 renderer。ZIP 只是本地导入载体，不能上传新的脚本、组件、Wasm 或依赖。试点仍走同一静态构建、原 URL、chrome、搜索、sitemap 和文章 RSS；none 页面不得吸入站点外壳。

第一个 renderer 不需要通用插件系统；出现第二个真实消费者后再评估抽取注册表。公网管理上传或可信源码包会改变权限与代码执行边界，必须另行评审，不能由本 ADR 自动授权。
