# ADR-0017：首页入口去重与侧栏内分层

- 状态：Accepted
- 日期：2026-08-30

## 背景

首页门户完成后，同一批目标页面同时出现在全局侧栏、“站内入口”面板、资料卡与顶部信号条中；“学习笔记”又同时作为侧栏一级入口和“探索”体系的一部分。重复入口没有增加内容发现能力，反而稀释了最近写作和学习笔记的层级。桌面二级菜单向内容区飞出，也打断了固定侧栏应有的空间边界。

## 审查结论

1. 首页标题、站点说明、信号条和资料卡存在身份与数量信息重复；保留信息最完整且与个人身份直接相关的资料卡。
2. “站内入口”完全复述全局导航，应删除，而不是继续做显示开关。
3. “笔记”属于探索型内容，应进入“探索”子层，不再占用一级导航位置。
4. 侧栏扩展应增加层级表达能力，而不是增加页面数量；本轮只连接已经存在且可用的路由。

## 决策

1. 独立搜索固定在侧栏最上方；品牌与从首页移入的站点说明紧随其后。
2. 首页删除大标题、说明、横向信号条和“站内入口”，以可访问的隐藏一级标题保留文档结构，首屏直接进入门户。
3. “主题”和“探索”使用原生 `details`，在侧栏内部展开带编号、纵向关系线和进入动画的二级结构；同一时间只展开一个层级。
4. “学习笔记”成为“探索”的首个子项；项目、能力、时间线与标签维持现有入口，不新增页面。
5. 门户设置只控制长期主题、发表日历和标签；旧版 `localStorage` 中的 `gateway` 字段在读取时被丢弃。
6. 移动端保持顶部壳，但搜索仍独立可见，站点说明和分层导航进入可滚动菜单。

## 后果

- 全局导航成为唯一的功能目录，首页专注内容与个人状态。
- 侧栏分层可以继续消费现有主题集合和功能注册表，不需要为每次扩展改写首页。
- 新入口仍必须先有真实内容、既有路由、移动回流和构建测试；侧栏本身不作为创建空页面的理由。
