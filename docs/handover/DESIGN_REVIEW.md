# 设计审查

审查对象：`prototype/index.html` 与历史架构方案。

审查方式：源码检查 + 1280 × 720 桌面视口 + 390 × 844 移动视口实际渲染；覆盖首页、文章页和粒子实验页。

## 总体评价

视觉方向成熟且辨识度高。“天文台”隐喻、深空蓝、矿物玉、黄铜和鸢尾紫形成一致语言；中文衬线正文与无衬线界面分工清楚。原型不是普通主题套壳，已经有效证明“外壳分档”和“主题即数据”的体验价值。

## 设计优势

- 首页建立了清楚的品牌层级：品牌、主标题、说明、指标、文章列表和实验室入口依次展开。
- 文章页行长、行高、标题节奏、首字下沉、代码块、表格和 callout 形成完整长文系统。
- 实验页确实呈现不同于正文页的空间感，返回桥清晰，没有把标准导航硬塞进作品页面。
- 四套主题由 CSS 变量驱动，Canvas 与 DOM 共用令牌，符合“主题是数据”的方向。
- 动效有 `prefers-reduced-motion` 分支；Canvas 限制 DPR、页面不可见时暂停更新，体现性能意识。
- skip link、焦点样式、语义标题和导航标签已有良好基础。

## 发现与优先级

### P0：移动端顶栏横向溢出

390px 视口下首页测得 `scrollWidth=500`、`clientWidth=380`。品牌、三项导航、主题按钮和沉浸按钮全部保持在 64px 顶栏，导致页面可横向滚动且右侧控件被裁切。

建议：在正式迁移中使用移动导航或两级信息优先级。小屏只保留品牌与菜单入口，将主导航和次级操作放入可键盘操作的抽屉/弹层；不要仅压缩字号。

### P0：原型路由与正式内容身份冲突

当前路径是 `#/post/architecture`。这适合单文件原型，不适合生产站。正式实现必须生成 `/posts/architecture/` 等真实静态路径，并直接提供正确标题、canonical、OG、RSS 和 sitemap。

### P0：`none` 的隔离尚未被实现证明

原型通过 CSS 隐藏 header/footer，但页面仍运行统一的 store、router、主题菜单、toast 和背景 Canvas。正式实现要从构建产物证明 `none` 不注入标准 chrome CSS/JS 和第三方服务，而不是只检查元素是否隐藏。

### P1：浮层可访问性不完整

帮助浮层缺少 `role="dialog"`、`aria-modal`、初始焦点、焦点循环和关闭后的焦点恢复；主题按钮/菜单缺少完整的 `aria-expanded`、方向键和 Esc 行为契约。正式组件应按可访问性模式实现并测试。

### P1：移动端信息层级需重新编排

文章正文与实验页在 390px 下基本可用，但首页 hero 首屏较长，文章列表入口下沉；实验页操作提示在移动端被完全隐藏。应为触屏提供简短、非悬停的操作提示，并验证 360px 和横屏。

### P1：字体与真实网络条件尚未验证

原型依赖系统中文字体栈，因此不同平台的字重、字面和换行可能明显变化。正式工程要决定“系统字体优先”还是自托管可变字体，并将字体加载、授权、子集化和 CLS 纳入预算。

### P2：装饰层要与内容性能解耦

全站 Canvas 很有品牌价值，但标准阅读页应允许低功耗/无动效模式，并测量移动设备的主线程与电量影响。装饰失败时正文仍应完整可用。

## 正式迁移的视觉验收

- 1280px 首页、文章页和实验页与原型保持核心层级和视觉气质；
- 390px 不横向溢出，导航与全部关键操作可达；
- 200% 文本缩放后无内容遮挡；
- 键盘可打开、操作、关闭主题菜单与帮助对话框；
- 减弱动效下没有持续动画，实验页仍有清楚的静止状态；
- 深色主题的正文、弱化文字、边框和焦点态通过对比度检查；
- 标准文章无 JavaScript 时仍显示完整正文、页内链接和上下篇链接。
