# 博客系统重设计、叙事展示与本地维护平台实施方案

状态：2026-08-29 进入实施  
范围：首页视觉、媒体管线、求解器回放、ArcVellum 文档站、学习笔记、本地 Blog Studio、个人信息与全站用语。

## 1. 批判性结论

当前站点已经有内容集合、三档页面外壳、构建审计、搜索、SEO、评论边界和可运行 Wasm 等工程骨架，但“功能已经存在”和“功能被正确表达”之间仍有明显落差。

1. 首页视觉主次倒置。`继续阅读` 占大区，长期主题却被压进窄轨道；这与“博客由持续发展的主题组织”的内容战略相反。主题应成为左侧主索引，近文只承担右侧三条短入口。
2. 封面组件把不同图源一律 `object-fit: cover`，并为不同位置设置 3:1、5:4、4:3、16:7 等互不兼容的裁切框。结果是资产通过了存在性检查，却在真实页面丢失主体。封面需要一个稳定的桌面画幅规范；正文插图则不能继承封面规则。
3. 求解器展示只回放识别路径，完整规划仅输出字符串。它证明了“调用过 C 内核”，却没有证明箱子真的被推、炸弹真的清墙、最终路径连续可执行。
4. ArcVellum 已有文章按“产品 / 前端 / 内核 / Runtime / 发布”粗分，仍不足以覆盖实际仓库的模块边界。真实工程至少还有 Narrative Projection、Orrery layout/rendering、Context Broker、Source Ingest、Prompt Registry、Style Compiler、Review CI、Workflow State Machine、Reader Contract、Longform Budget、Character Engine、发布与证据等独立主题。
5. 学习笔记作为 `chrome:none` 主题只是模拟知识库。它没有本地导入、真实文件索引、资源同步或发布状态，因此不能声称“本人可用”。学习笔记应退出主题集合，成为独立内容集合和同步工作流。
6. 顶部品牌只返回首页，个人身份被埋在 About 页面；品牌触点没有承担作者入口。需要把左上角变成可访问、可扩展的个人资料抽屉，同时保留清晰的首页链接。
7. “阅读编排器”与用户目标冲突，应删除，不再用推荐算法制造首页功能密度。

## 2. 视觉与媒体决策

### 2.1 首页版式

桌面端采用 `主题 2fr / 继续阅读 1fr`：

- 左侧主题区为固定视觉高度的纵向滑动窗口；卡片使用完整 16:9 缩略画布、主题名、两行简介和文章数。
- 右侧只显示三篇文章，使用紧凑目录行；日期、标题和主题身份优先，摘要只保留必要行数。
- 两区不做机械等高：右侧向下错位半个标题高度，形成编辑版面的节奏，但不破坏阅读顺序。
- 900px 以下回流为单列，主题仍先于继续阅读；320 CSS px 仍不得产生页面级横向滚动。

### 2.2 封面与正文插图

- 所有内容封面统一为 16:9 桌面画布。图片完整性优先于铺满：真实图片默认 `contain`，空余区域由内容强调色、暗化底图或纸面纹理吸收，而不是裁掉主体。
- 默认封面 SVG 同步改为 16:9，避免真实图与缺省图切换时版面跳变。
- 文章 hero、列表、主题卡与相关文章共享画幅契约，只改变显示尺寸，不改变裁切语义。
- 正文媒体独立：`img/picture/video/svg` 使用 `max-inline-size:100%`、`block-size:auto`；支持窄图、宽图、全宽图、浮左、浮右、居中和带说明图，不限定比例。
- Markdown 默认图片按原比例居中。作者可通过 `<figure class="media-wide|media-left|media-right|media-bleed">` 显式控制位置；移动端全部回流为单列。
- 保留图片的固有宽高或 CSS `aspect-ratio` 预留空间，降低加载位移。

## 3. 求解器展示器

不修改求解规则、路径协议和 C 求解内核。展示层只消费 C/Wasm 返回的识别末状态与规划路径，并按 `anim_engine.c` 的既有语义确定性重放：

- 大写 `UDLR` 是行走；小写是推送。
- 小写步进入箱子或炸弹所在格，实体沿同方向移动一格。
- 炸弹推入墙格时，炸弹到达该格并引爆，清除中心 3×3 内的墙，随后从活动实体中移除。
- 箱子到出口后保留完成视觉并计入完成数。

展示新增：识别 / 完整规划轨迹切换、逐步状态快照、当前动作、完整路径分段视图、推动高亮、3×3 爆炸波、已清除墙闪回、箱弹计数、可拖动时间轴、初始 / 识别后 / 规划结束三种视图。JS 不计算解，只负责验证性回放；出现非法路径时停止并明确报错。

## 4. ArcVellum 展示与编辑体系

### 4.1 内嵌叙事星仪 Demo

栏目入口增加一个明确标注 `SIMULATED PROJECT / REAL ARCHITECTURE` 的展示 Demo。数据是演示数据，信息结构遵循实际技术路线：

`project facts -> Narrative Projection v4 -> focus / relation / layout hints -> deterministic layout -> renderer / DOM overlays -> detail/action ports`

Demo 包含：

- 书 / 章 / 场景 / 人物四级焦点；
- Spine、Braid、Strata、Constellation、Loop、Stage 六种空间语法；
- 作品主脉 / 全部事实密度切换；
- 章节核、场景轨、人物关系、审查/任务/正文信号；
- 节点详情、当前生命周期、来源证据、可用动作；
- 场景总量、正文字符、审查、阻断与 revision 指标；
- 键盘可用的列表替代视图和减少动效模式。

实现不是二维 DOM 星图换皮，而是从实际 `parallaxProjection.ts` / `NarrativeParallaxRenderer` 路线缩编：Pixi.js WebGL 画布负责确定性天穹、仪轨、关系和星核；DOM 文字层负责可读标签与命中；拖动使用与正式工程同参数的单位四元数轨道，投影与 `depthScale` 保留正式比例；章节核和本章场景使用实际布局思想的确定性黄金角聚类。完整产品的 `pixi-viewport`、后端投影、窗口系统和动作端口不复制到博客，避免把文档 Demo 冒充客户端。

这不是复制原项目，也不伪装成连接真实后端；它是对真实架构边界的可交互解释。

### 4.2 内容分层

ArcVellum 内容按五层维护：

1. 产品与使用：项目建立、正式创作闭环、阅读、交付、Beta 边界。
2. 文学内核：Canon、人物、剧情场景、上下文、字数预算、读者体验、文风。
3. Agent 与工作流：任务包、CLI 中介、Provider、Prompt Registry、审查、晋升、恢复。
4. 空间前端：Narrative Projection、空间语法、布局、渲染、窗口系统、可访问视图、性能。
5. 工程与发布：模块边界、应用端口、持久化、事件、Tauri/sidecar、更新、证据与测试。

本轮交付独立的编辑清单，逐项映射源文档、代码模块、文章状态与依赖；当前文章同步扩充并在导航中分组。

## 5. 学习笔记与 Blog Studio

### 5.1 学习笔记

- 从 `columns` 中移除 `learning-notes`。
- 新建独立 `notes` 内容集合和 `/notes/`、`/notes/[...slug]/` 页面。
- 支持 Markdown/MDX、标签、别名、反向链接、更新时间、发布状态、附件和源路径摘要。
- 提供本地同步命令，接受 Obsidian/Vault 目录，复制 Markdown 与附件，转换基础 `[[wikilink]]`/嵌入链接，并生成同步清单；默认只发布 frontmatter 显式声明公开的笔记。
- 公开站永远只读；同步必须由本机命令或本机 Studio 发起。

### 5.2 Blog Studio v0.1

本机 Node 服务，绑定 `127.0.0.1`，不进入公开构建。界面参考 VS Code 的信息架构而非皮肤复制：Activity Bar、Explorer、Editor/Preview、Panel、Status Bar。

首版可用能力：

- 浏览文章、主题、笔记和资源树；
- 创建文章、主题和笔记模板；
- 读取/编辑允许目录内的文本文件；
- Markdown 即时预览、frontmatter 表单和未保存状态；
- 选择本地笔记目录并执行预览同步 / 正式同步；
- 运行内容审计、封面审计、测试、构建；
- 展示日志和失败原因。

安全边界：路径必须解析并校验在白名单根目录；拒绝 `..`、符号链接越界、二进制覆盖和任意 shell；命令来自固定注册表而非用户字符串；没有公网监听、账号系统或云同步。生产发布仍走现有部署脚本，本轮不把部署令牌暴露给浏览器。

## 6. 个人信息与词汇迁移

- 左上品牌改为打开资料抽屉，抽屉含头像、短简介、当前关注方向、GitHub 和预留社交链接区；提供关闭按钮、遮罩、Escape、焦点恢复和滚动锁。
- 顶栏继续保留独立“首页”。
- 页脚加入 GitHub 主页链接。
- 所有读者可见的分类术语从“栏目”迁移为“主题”。内部 collection 名 `columns` 和稳定 URL `/columns/` 暂不改，避免无价值的迁移风险；搜索、SEO 标签和说明文案全部改为“主题”。

## 7. 实施顺序

1. 先修媒体契约与首页主次，删除阅读编排器，完成词汇与个人资料抽屉。
2. 完成求解器的真实规划重放与交互状态。
3. 增加 ArcVellum 星仪 Demo、模块化文章清单和新增/重构文章。
4. 将学习笔记迁出主题，增加内容集合、页面与同步器。
5. 实现 Blog Studio v0.1 和固定命令注册表。
6. 执行内容、类型、单元、构建、链接、预算和浏览器视觉验收。

## 8. 验收门槛

- 所有真实封面在 16:9 容器中完整可见，无主体裁切；缺省封面也为 16:9。
- 正文横图、竖图和窄图保持原比例；320px、390px、桌面宽度无页面级横向溢出。
- 首页桌面端主题左大、继续阅读右小且恰好三篇；主题窗口可独立滚动，卡片不变形。
- 公开页面不再出现“阅读编排器”，读者可见分类名统一为“主题”。
- 顶部资料抽屉可用鼠标和键盘打开/关闭；页脚 GitHub 链接有效。
- 求解器完整规划路径可逐步回放；至少一张含箱子推动和炸弹爆破的地图通过浏览器验证。
- ArcVellum Demo 在桌面和移动端可操作，明确标识模拟数据，并提供无障碍列表视图。
- ArcVellum 编辑清单覆盖仓库主要模块和关键阶段文档，不把未来项冒充已完成文章。
- 学习笔记不再出现在主题目录；本地同步 dry-run、正式同步、反向链接和附件路径各有自动测试。
- Blog Studio 只绑定回环地址，路径越界测试失败，文章/主题/笔记创建与审计命令可运行。
- `pnpm verify` 通过；浏览器无控制台错误、破图、不可达按钮和非预期横向滚动。

## 9. 外部标准依据

- W3C WCAG 1.4.10 Reflow：普通内容在等效 320 CSS px 宽度下不应要求双向滚动；复杂图形可以局部例外，但不能拖累整页。
- web.dev Responsive Images：`contain` 保留完整图像，`cover` 会裁切；两者必须按媒体语义选择。
- web.dev CLS：图片提供固有尺寸或预留 `aspect-ratio`，避免加载导致的版面位移。
- Astro 官方内容集合与图片说明：本地内容图使用 schema `image()` / imported metadata，不能把本地路径字符串直接传给图像组件。
- VS Code 官方 Workbench：Activity Bar、Side Bar、Editor Group、Panel、Status Bar 是维护平台的信息架构参考。
- File System Access API 需要用户授权、受浏览器支持和安全上下文限制，因此本轮以本机 Node 白名单服务作为可靠主路线，目录选择 API 只作为增强，不作为唯一写入路径。
