## 二、部分完成或确实漏项

### P0：文章普遍不够长，且正文配图明显不足

- 24 篇文章的正文字符数中位数约为 2161；其中 20 篇不足 2500 字符。
- 只有 1 篇常规 MDX 文章含正文内联图片或 figure。大部分内容只有封面，尚未达到“文章也可以配图”所期待的编辑质量。
- `particle-field` 是全屏交互实验，不能用普通文章字数衡量；其余短文仍需逐篇依据真实项目文档扩写，而非通用填充。

验收标准：每篇项目文章先形成证据清单，再补架构图、真实截图、状态流图或结果图；图片拥有用途说明、替代文本和移动端行为。

### P0：ArcVellum 内容体系只完成首批，不是“全面写完”

- 当前已有 12 篇发布或可阅读内容，但编辑 backlog 仍有 38 个待写条目，另有 7 个可扩写条目。
- 模块化分层清单已经完成，真实开发叙事也已进入现有文章；然而“每个功能模块均形成独立文章”仍属于后续编辑工程。

验收标准：按内核、运行时、Agent、工作流、前端投影、数据与交付六层逐批关闭 backlog；每篇都引用实际代码、设计文档或开发痕迹。

### P1：学习笔记可用链路存在，但尚未接入真实个人笔记库

- 本地目录同步、公开只读页和维护入口已经可用。
- 当前公开内容只有一篇系统说明性质的欢迎笔记；没有证据表明真实 Obsidian/个人 vault 已完成首次导入与持续同步。

验收标准：配置实际 vault 路径，完成一次 dry-run、一次显式同步、附件映射与冲突恢复测试，再导入一组真实可公开笔记。

### P1：Blog Studio 尚未形成“发布”闭环

- Studio 已支持文章/主题/笔记创建、编辑、保存、预览和本地命令。
- 生产发布仍交给 Git 与部署流水线，Studio 内没有发布审批、构建结果、版本记录和回滚界面。

验收标准：将校验、构建、提交、部署预检与发布状态接成受控命令；默认只绑定 `127.0.0.1`，发布动作必须显式确认。

### P1：Studio 文件边界仍需加固

- 当前路径校验覆盖词法路径越界，但未完整执行 `realpath` / `lstat` 的符号链接边界校验。
- Studio 与笔记同步缺少独立自动化测试，现有架构测试不能替代读写安全测试。

验收标准：拒绝内容根目录内指向外部的符号链接，并增加越界、冲突、附件、失败恢复和只读预览测试。

### P1：视觉资产“技术合格”不等于“艺术统一”

- 资产审计为 28 张真实封面、2 张确定性默认封面，且没有 Astro 本地图片导入错误。
- 不同来源图片的构图、色温和留白仍不一致；`contain` 可以避免裁切，却会暴露非 16:9 源图的留边。
- 正文缺图比封面裁切更影响博客的完成感。

验收标准：为每个主题建立 art-direction 模板；对重点文章制作专属 16:9 桌面封面，并补齐正文中的证据性图片，而不是仅靠默认封面。

### P2：生产部署与真实质量数据仍依赖外部配置

- 域名、DNS、Cloudflare 账户、评论与统计服务仍需站点所有者决策或凭据。
- 本地构建与 E2E 通过不能替代生产环境的 Core Web Vitals、社交卡片、RSS、404 与缓存策略验收。
