# 开发原则与设计哲学

状态：已接受，作为后续实现的默认约束。

## 设计哲学

### 1. 文章有稳定身份，外观可以自由

一篇文章无论采用标准长文、特殊版式还是全屏实验，都必须保有同域规范 URL、可索引的元数据，并进入统一的 sitemap、RSS 与搜索体系。自由发生在呈现层，不以牺牲内容身份为代价。

### 2. 外壳是加法，不是逃生

基础布局只提供有效 HTML 文档、`head` 契约和内容插槽。导航、页脚、目录、评论、统计和返回桥均为显式组合部件。`full` 不是不可摆脱的模板，`none` 也不是二等公民。

### 3. 自由度是一条渐进曲线

默认文章零配置进入 `full`。确有版式需要时使用 `minimal`；只有作品、实验和叙事页面才使用 `none`。每次升级自由度，都同时承担相应的可访问性、性能和维护责任。

### 4. 静态内容优先，交互按需赢得

文章正文首先是构建期 HTML。客户端 JavaScript 只用于真实的互动价值，例如主题、阅读偏好和实验组件；装饰性动效必须可暂停、尊重减弱动效偏好，并在不可用时保留可读内容。

### 5. 主题是语义数据

主题不应是散落的颜色覆盖。令牌以“背景、正文、弱化、强调、危险”等语义命名，DOM、Canvas、OG 图和代码高亮共享同一语义映射。组件依赖语义，不依赖某套主题的具体色值。

### 6. 共置优先于过早抽象

文章私有组件、脚本、样式和媒体与文章共置。只有第二个真实消费者出现后，才把能力提升为公共组件。公共层保持小、稳定且有清晰契约。

### 7. 原型表达意图，测试守住契约

原型用于说明体验，不作为生产结构模板。生产实现用 schema、架构测试、构建测试和浏览器测试把关键约束变成可执行断言。

## 开发原则

- 先等价迁移，再优化或重设计；任何视觉偏离都应有明确目的。
- 优先浏览器原生能力和 Astro 组件，避免为局部交互引入整站框架。
- 依赖最小化不是数字游戏；每项依赖必须减少长期总复杂度。
- 重要决策必须可追溯、可复审、可回滚；用 ADR 记录结论和代价。
- 对外部服务采用适配器与开关，未配置时构建仍应成功。
- 不把隐私、可访问性、安全和性能留到上线前补做。
- 文档描述当前真实状态，不使用“已完成”代表尚未验证的目标。

## 非功能基线

正式工程应满足：

- 支持宽度至少从 360px 到 1440px，任何核心页面不得横向溢出；
- 键盘可完成导航、主题、帮助浮层和阅读控制；
- 所有动效遵循 `prefers-reduced-motion`，Canvas 页面另提供明确的暂停方式；
- 标准阅读页在无 JavaScript时仍可阅读正文和使用普通链接；
- 路由输出真实路径而非 hash；每篇文章有 canonical、OG、结构化数据和可解析日期；
- `none` 档不自动加载站点 chrome、评论、统计或标准阅读脚本；
- 以 Core Web Vitals 的“良好”阈值为上线目标，并给标准页和实验页分别设预算；
- 内容 schema、链接、构建产物和代表页面视觉都进入 CI 验证。
