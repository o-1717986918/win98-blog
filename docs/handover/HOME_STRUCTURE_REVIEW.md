# 首页结构与扩展性审查

日期：2026-08-30

## 结论

首页的核心价值应是“识别人、进入写作、发现知识”，而不是再次罗列全站路由。当前生产结构保留资料卡、长期主题、最近写作、学习笔记、发表日历、标签与末尾精选；站点身份说明和全局路径由侧栏承担。

## 已处理问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 首页标题、说明、信号条与资料卡重复 | 首屏信息层级分散，像宣传首页 | 标题仅保留为可访问结构；说明移入侧栏；信号条删除 |
| “站内入口”复述侧栏 | 多条路径指向同一页面，增加扫描成本 | 删除面板及其偏好开关 |
| “笔记”同时是一级入口和探索能力 | 分类模型不一致 | 放入“探索”首个子项 |
| 二级菜单向内容区飞出 | 侧栏边界不稳定，遮挡首页 | 改为侧栏内部编号时间尺式展开 |
| 功能扩展依赖手工堆首页卡片 | 容易再次产生入口重复 | 入口继续由主题集合与功能注册表生成，首页只接内容模块 |

## 扩展规则

- 新能力先证明真实内容与既有路由，再决定是否进入“探索”；本轮不创建任何新页面。
- 首页新增模块必须提供侧栏或现有模块不能承担的新任务，不能只是另一组链接。
- 资料卡负责“人”，写作流负责“现在写什么”，学习笔记负责“知识如何生长”，主题和标签负责长期发现；模块职责不交叉。
- 桌面侧栏允许增加现有路由的子层，但必须保持单层展开、720px 高度可滚动和 320px 页面无横向溢出。
