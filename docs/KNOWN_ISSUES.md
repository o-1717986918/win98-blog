# 已知问题与架构风险台账

更新日期：2026-08-31  
适用分支：`main`  
状态说明：`已确认` 表示已有源码或测试证据；`待设计` 表示问题成立但修复边界尚未确定；`观察项` 表示当前风险较低，需要在功能扩张前处理。

本文只记录仍然存在的问题，不把改进设想写成既成事实。问题修复后应保留条目，并补充修复提交、验证方式和关闭日期。

## P1：发布与内容安全

### KI-001 完整 E2E 当前失败，发布门禁未形成闭环

- 状态：已关闭（2026-08-31）
- 证据：`tests/e2e/site.spec.ts` 写死首页和归档内容数量；当前运行结果为 14/16 通过，首页预期 23、实际 25，归档预期 24、实际 26。
- 风险：正常新增内容会破坏测试；`deploy:check` 只运行 `pnpm verify`，GitHub Pages 工作流只运行构建，因此 E2E 失败的版本仍可能部署。
- 完成条件：测试从内容源派生期望值或只验证行为不变量；所有生产部署依赖统一的完整验证命令。
- 修复与验证：E2E 已改为验证动态数量和行为不变量；CI、GitHub Pages 与 `deploy:check` 统一执行 `verify:all`。最终验证结果见本文末尾。

### KI-002 笔记同步不清理陈旧输出

- 状态：已关闭（2026-08-31）
- 证据：`tools/blog-studio/sync-notes.mjs` 只覆盖当前条目并重写 manifest，没有删除上一轮存在、本轮已删除或改名的输出目录。
- 风险：已撤回、删除或重命名的公开笔记可能继续发布；源知识库相对路径还会进入公开 HTML。
- 完成条件：基于前后 manifest 做差量清理；公开输出不包含源目录信息；增加删除、改名、公开转私有的回归测试。
- 修复与验证：同步器读取前一版 manifest，只删除经过 slug 与路径边界校验的托管目录；生成的笔记 frontmatter 不再包含源路径；同步回归覆盖删除与替换。

### KI-003 搜索产品承诺、运行实现和测试契约不一致

- 状态：已关闭（2026-08-31）
- 证据：搜索页宣称覆盖全部公开文章、主题与页面；`public/scripts/search.js` 强制 `type: '文章'`；架构测试和 E2E 又要求只能返回文章。
- 风险：Pagefind 已索引的笔记和页面不可发现，测试反而阻止修复。
- 完成条件：明确搜索范围，并让页面文案、索引 metadata、运行时过滤和测试使用同一契约。
- 修复与验证：统一为“全部公开 Pagefind 正文边界”；移除文章过滤器，页面文案、构建合同和 E2E 均验证公开笔记可发现。

## P2：架构一致性与可扩展性

### KI-004 架构文档、ADR、当前实现和工作区校验互相漂移

- 状态：已关闭（2026-08-31）
- 证据：最高优先级源文档仍描述旧 Astro、Satori、Client Router 和 Cloudflare 方案；`check-workspace.mjs` 固定旧文档 SHA，且未要求当前全部 ADR 存在。
- 风险：新开发者按文档实施会得到错误架构，修正文档又会触发人工 checksum 维护。
- 完成条件：确定唯一可更新的事实源；历史设计转为 ADR；自动校验结构和必要文件，不冻结整份文档内容。
- 修复与验证：README 明确可执行事实的权威顺序；源架构文档改为历史基线并校准当前实现；新增 ADR-0018；工作区检查不再冻结整文件 SHA，并要求 ADR-0014 至 ADR-0018 与两套发布 workflow 存在。

### KI-005 同日期内容缺少确定性业务排序

- 状态：已关闭（2026-08-31）
- 证据：文章和笔记主要只按日期排序；大量内容共享同一天；`featured` 没有唯一性约束。
- 风险：首页、归档、上一篇/下一篇和相关推荐顺序依赖加载顺序，内容增长后会发生无意重排。
- 完成条件：引入明确的 `order`/`sequence` 或稳定次级键；校验焦点文章基数。
- 修复与验证：文章、笔记、归档和相关推荐在日期相同后统一以内容 ID 稳定排序；内容审计要求 `featured` 最多一篇。

### KI-006 内容、导航和展示信息存在多套手工登记表

- 状态：已关闭（2026-08-31）
- 证据：ArcVellum 文档元数据同时存在于 Content Collection 和 `src/components/arcvellum/docs.ts`；项目、技能、时间线、入口开关和部分统计数字另由 `src/config/portal.ts` 手工维护。
- 风险：已经出现“12 篇”与实际 14 篇不一致；新增门户能力需要跨配置、页面、导航、测试和文档同步修改。
- 完成条件：从内容集合派生目录、计数、分组和可用入口；只保留无法派生的人工配置。
- 修复与验证：ArcVellum 编号由顺序生成、标题从 Content Collection 获取；探索导航集中为只包含已实现页面的注册表；删除虚构的关闭功能开关和硬编码篇数。人工配置只保留项目说明、能力证据、里程碑和文档分组等编辑判断。

### KI-007 Frontmatter 和发布语义存在多套解析路径

- 状态：已关闭（2026-08-31）
- 证据：Astro Content Collection 使用 Zod；路由集成使用 `yaml.parse`；架构测试继续通过正则表达式解析 frontmatter。`columns` 在 Schema 中可为空，内容审计只禁止已发布文章为空，架构测试却禁止所有文章为空。路由集成只把启动时发现的具体文件加入 `addWatchFile`；Astro 7.2.9 只在变更路径与该列表精确匹配时重启配置，因此开发态新增文件不会触发路由重新注入。
- 风险：字段默认值、迁移别名、草稿和布局语义可能产生漂移；新内容可能已经进入集合，却要重启开发服务器后才有页面路由。
- 完成条件：抽取可复用的规范化 metadata 层；Schema 作为业务不变量事实源；移除正则解析；为路由发现增加目录级新增事件处理，并验证开发态新增、删除、重命名内容。
- 修复与验证：路由解析复用 Astro Zod 的 chrome/draft Schema，发布文章主题引用进入 Content Schema；新增内容由 Vite watcher 触发开发服务器重启，删除仍由现有 `addWatchFile` 路径触发。解析与新增事件均有单元测试。

### KI-008 公开笔记图谱按全部笔记而非可发布集合校验

- 状态：已关闭（2026-08-31）
- 证据：`check-content.mjs` 将草稿和私有笔记加入合法目标集合，实际路由只发布 `publish && !draft`。
- 风险：公开笔记引用私有目标时审计通过，线上关系静默消失。
- 完成条件：以公开集合构建路由和名称索引；未解析的显式关系在构建阶段失败或要求显式豁免。
- 修复与验证：内容审计与笔记页面均只用 `publish && !draft` 集合构图，公开笔记指向私有、草稿或不存在目标会让构建失败。

### KI-009 浏览器存储失败会中断核心界面脚本

- 状态：已关闭（2026-08-31）
- 证据：侧栏、开场动画、环境效果和门户控制分别直接访问 `localStorage`/`sessionStorage`，没有统一异常边界。
- 风险：受限浏览器中移动菜单可能失效，开场遮罩可能停留在正文上方。
- 完成条件：统一安全存储适配器；核心交互不依赖存储成功；增加 Storage API 抛错回归测试。
- 修复与验证：新增统一安全存储适配器并迁移侧栏、开场、环境场、门户和阅读控件；Playwright 覆盖 Storage API 全部抛错时的开场退出、移动导航、焦点恢复和门户设置。

### KI-010 性能预算接近上限且统计维度不等于用户加载成本

- 状态：已关闭（2026-08-31）
- 证据：当前构建约为 JS gzip 157/180 KiB、单页 CSS 76/80 KiB、全站 CSS 198/200 KiB。
- 风险：脚本已经明确把全站 CSS 定义为维护预算，而非用户传输预算，因此指标本身并非错误；真正问题是余量只剩约 2 KiB。JS 总量仍不能准确反映单条路由加载多个 chunk 的聚合成本。
- 完成条件：基于路由依赖图衡量首屏和交互传输成本；另设仓库资源体积预算，不混用两类指标。
- 修复与验证：体积检查现在从每页脚本入口递归计算静态与懒加载 chunk，独立报告 route reachable JS、单页 CSS 和仓库 route-isolated CSS；仓库维护预算与单页传输预算分离。

### KI-011 非内容寻址资源被设置为长期 immutable

- 状态：已关闭（2026-08-31）
- 证据：`/brand/*` 和 `/og/*` 使用一年 immutable，但 URL 不带内容哈希。
- 风险：Logo、文章标题、描述或主题更新后，客户端和社交抓取器可能长期展示旧内容。
- 完成条件：稳定 URL 使用可重验证缓存，或为生成资源加入内容版本。
- 修复与验证：`/brand/*` 与 `/og/*` 改为短期缓存并允许 stale-while-revalidate，不再声明 immutable。

### KI-012 部署配置和主机能力没有统一验证

- 状态：部分修复；剩余为主机外部边界（2026-08-31）
- 证据：缺少环境变量时生产 URL 回退到 `https://example.com`；当前使用 GitHub Pages，但 `_headers` 不会由 GitHub Pages 应用；Umami 脚本地址未执行与其他外部服务一致的 HTTPS 校验。
- 风险：手工构建可生成错误 canonical/RSS/OG；文档声明的安全响应头在线上并不存在。
- 完成条件：生产构建强制要求站点 URL；将安全头放到真实承载层；统一验证第三方脚本来源。
- 修复与验证：部署检查拒绝缺失、非 HTTPS、localhost/example.com 的站点 URL，并验证 Umami 脚本 HTTPS；本地回退改为 localhost，避免伪生产域名。GitHub Pages 不支持仓库 `_headers`，部署文档和验收表已明确必须在真实承载层核验；迁移到可控响应头的主机前，此项不伪装为完全关闭。

### KI-013 搜索摘要通过 `innerHTML` 注入

- 状态：已关闭（2026-08-31）
- 证据：Pagefind excerpt 未经过本地白名单清洗直接写入 `innerHTML`，其他字段则经过转义。
- 风险：当前内容可信时风险较低；未来接入外部内容后会成为 HTML 注入边界。
- 完成条件：只允许 Pagefind 的 `<mark>` 标签，或通过 DOM API 构造结果。
- 修复与验证：摘要先整体 HTML 转义，再只恢复精确的 `<mark>`/`</mark>`；构建合同防止移除该边界。

### KI-020 架构测试主要冻结源码写法，没有验证依赖边界

- 状态：已关闭（2026-08-31）
- 证据：`src/tests/architecture.test.ts` 共 342 行，不导入任何生产模块；它读取源码 81 次，包含大量 `toContain`/`not.toMatch` 断言。注释或不可达代码可以满足正向断言，等价的模板重构则会造成失败。none 路由检查只搜索直接入口文件，无法发现内容组件或传递依赖引入站点 shell。
- 风险：测试维护成本随重构增长，却仍可能漏掉真正的依赖越界；搜索过滤已经出现“错误实现被测试保护”的实例。
- 完成条件：数据规则回到 Schema；模块边界使用依赖图或静态导入规则；页面契约检查最终 HTML、资源引用和无 JavaScript 可读性；源码字符串测试只保留少量不可替代的政策哨兵。
- 修复与验证：架构测试缩减为六项可执行合同，实际导入站点配置、解析 frontmatter 并递归检查 Base/none 的传递依赖；视觉与功能合同继续由最终 HTML 审计和 Playwright 负责。

## P3：维护性与交互完整度

### KI-014 日期逻辑没有统一站点时区

- 状态：已关闭（2026-08-31）
- 证据：文章归档使用 `Asia/Shanghai`，发布日历和部分笔记日期使用运行环境本地时区；RSS 构建时间使用当前时钟。
- 风险：本地和 CI 对带时间戳内容的日期归属不同，相同源码的 RSS 也不可复现。
- 完成条件：集中定义站点时区和日期工具；RSS 时间由最新内容时间派生。
- 修复与验证：统一 `Asia/Shanghai` 日期工具并覆盖 UTC 跨日测试；首页数据属性、发表日历、归档和笔记共同使用；RSS `lastBuildDate` 取最新内容日期。

### KI-015 首页和核心交互组件正在重新单体化

- 状态：观察项
- 证据：`SiteIntro.astro`、首页、`SiteHeader.astro` 和 `AmbientField.astro` 同时承担较多数据、样式和状态职责。
- 风险：继续增加综合门户功能后，首页和侧栏会成为新的集中耦合点。
- 完成条件：拆分数据装配、视图模型、纯展示区块和共享交互状态；保持页面只负责编排。

### KI-016 展示组件内部查询集合，数据依赖隐式

- 状态：观察项
- 证据：`PostList.astro`、`ArchiveTimeline.astro`、`SiteHeader.astro` 等组件自行调用集合查询。
- 风险：重复读取、排序和转换数据，组件难以独立测试和复用；内容规模扩大后构建成本增长。
- 完成条件：由页面或集中查询层提供稳定的 view model，展示组件只接收 props。

### KI-017 存在重复组件和分散的站点身份配置

- 状态：已关闭（2026-08-31）
- 证据：两个 `LabColumn.astro` 内容完全相同且其中一个未使用；作者名、GitHub、站点名分散在文章、页脚、SEO、开场和社交图代码中。
- 风险：重命名、迁移和多作者扩展容易遗漏。
- 完成条件：删除无引用副本；建立单一站点身份配置并由 SEO、UI 和社交图消费。
- 修复与验证：删除未引用的重复组件；站点标题、作者与 GitHub 由 `src/config/site.ts` 统一供关于页、页脚、SEO、开场和分享图消费。

### KI-018 键盘焦点和客户端异常反馈不完整

- 状态：已关闭（2026-08-31）
- 证据：移动菜单按 Escape 关闭后不恢复触发按钮焦点；分享和剪贴板拒绝没有统一错误处理。
- 风险：键盘用户可能进入隐藏区域，受限浏览器出现无反馈失败。
- 完成条件：实现焦点恢复、操作状态提示和异常兜底，并加入键盘 E2E。
- 修复与验证：移动菜单 Escape 后恢复触发按钮焦点；复制、分享和取消都有 live status；Playwright 覆盖焦点与 API 拒绝路径。

### KI-019 辅助入口与链接检查存在盲区

- 状态：已关闭（2026-08-31）
- 证据：`llms.txt` 指向不存在的首页 fragment；链接检查只验证目标文件，不验证锚点；独立搜索页仍包含旧“顶栏”表述。
- 风险：机器入口和辅助导航可在构建全绿时失效。
- 完成条件：验证站内 fragment；清理或重构冗余搜索路由；将辅助入口纳入行为测试。
- 修复与验证：链接检查会解析最终 HTML 的 fragment ID，`llms.txt` 已改到真实主题锚点；搜索页清除旧顶栏表述并进入搜索 E2E。

### KI-021 `back:false` 的 standalone 页面仍携带 BackBadge 样式

- 状态：已关闭（2026-08-31）
- 证据：`StandaloneLayout.astro` 静态导入 BackBadge 后再做条件渲染；当前 `dist/columns/arcvellum/index.html` 没有返回按钮 DOM 和脚本，但仍包含 `.back-badge` CSS。
- 风险：当前体积很小，但说明“可选组件”没有形成资产级隔离，源码字符串测试也无法发现这一点。
- 完成条件：明确这是可接受的共享成本，或把带返回入口和完全 content-only 的 standalone 路径拆开，并对最终资源建立断言。
- 修复与验证：BackBadge 样式改为随组件条件渲染的 inline 样式；最终 `back:false` ArcVellum 产物不再包含 DOM 或 `.back-badge` CSS，构建合同验证该结果。

### KI-022 已完成的数据迁移仍长期保留在运行时 Schema

- 状态：已关闭（2026-08-31）
- 证据：Schema 仍接受 `graphite`、`paper`、`night`、`indigo` 并静默映射到 `mist`/`abyss`，但当前内容中已不存在这些旧值。
- 风险：源文件语义与运行时语义不同，拼写或旧模板问题被长期掩盖；未来工具必须继续理解历史别名。
- 完成条件：确认所有内容和导入工具已迁移后，Schema 只接受当前主题值；如需导入旧数据，在一次性迁移层转换而不是在核心 Schema 中长期兼容。
- 修复与验证：Content Schema 与运行时主题解析器只接受 `mist/abyss`；旧别名说明已从操作文档和公开文章更新，ADR-0018 取代旧兼容决定。

### KI-023 构建过程没有固定的发布时间快照

- 状态：已关闭（2026-08-31）
- 证据：路由注入在配置阶段使用一次 `Date.now()` 判断定时文章，`isPublishedForPreview` 又在每次集合过滤时重新调用 `Date.now()`。
- 风险：文章若恰好在一次较长构建中到达发布时间，早期可能没有注入文章路由，稍后的首页、归档或 RSS 却已经把它列为公开内容；链接检查最终可能让构建失败，但不同页面也可能在临界时刻得到不同集合。
- 完成条件：每次构建只生成一个不可变的 publication timestamp，并让路由发现、集合过滤、RSS、归档和测试共同使用。
- 修复与验证：新增进程级 publication clock，配置阶段初始化并通过环境值共享；路由注入、集合过滤、发表日历和页脚年份使用同一快照。
